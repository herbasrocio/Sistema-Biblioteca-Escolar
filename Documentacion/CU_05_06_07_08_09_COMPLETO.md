# CU 05 - GESTOR DE CATÁLOGO

## CU-05.1: Registrar Material

**Actor Principal:** Bibliotecario, Administrador

**Precondiciones:**
- El usuario ha iniciado sesión
- El usuario tiene permisos para registrar materiales

**Postcondiciones:**
- Se ha creado un nuevo material en el catálogo
- El material está disponible para préstamos

### Flujo Principal:
1. El usuario accede al módulo "Registrar Material"
2. El sistema muestra el formulario de registro
3. El usuario ingresa los datos del material:
   - Título (obligatorio)
   - Autor (obligatorio)
   - Tipo (Libro/Revista/DVD/CD/Otro)
   - Género (obligatorio)
   - Editorial
   - ISBN
   - Año de publicación
   - Cantidad total
4. El usuario confirma el registro
5. El sistema valida los datos ingresados
6. El sistema genera un GUID para el material
7. El sistema guarda el material en la base de datos
8. El sistema registra la operación en la bitácora
9. El sistema muestra mensaje de éxito

### Flujos Alternativos:
**5a. Datos inválidos:**
- El sistema muestra mensaje de error específico
- Retorna al paso 3

### Información Específica:
- **Formulario:** `registrarMaterial.cs`
- **Clase BLL:** `MaterialBLL.cs`
- **Método:** `GuardarMaterial(Material material)`
- **Validaciones:** Título, autor, género obligatorios; cantidades no negativas

---

# CU 06 - GESTOR DE USUARIOS

## CU-06.1: Crear Usuario

**Actor Principal:** Administrador

**Precondiciones:**
- El usuario tiene permisos de administrador

**Postcondiciones:**
- Se ha creado un nuevo usuario con rol asignado

### Flujo Principal:
1. El administrador accede a "Gestión de Usuarios"
2. El administrador selecciona "Nuevo Usuario"
3. El sistema muestra formulario
4. El administrador ingresa:Nombre de usuario (único), Email, Contraseña (mínimo 6 caracteres) y Rol (Administrador/Docente/Bibliotecario)
5. El administrador confirma
6. El sistema valida los datos
7. El sistema crea el usuario
8. El sistema hashea la contraseña con SHA-256
9. El sistema asigna automáticamente el rol seleccionado
10. El sistema calcula el DVH
11. El sistema registra en bitácora con gravedad "Alto"
12. El sistema muestra mensaje de éxito

### Flujos Alternativos:
**6a. Usuario duplicado:**
- El sistema muestra "Ya existe un usuario con ese nombre"
- Retorna al paso 4

**6b. Email inválido:**
- El sistema valida formato email
- Retorna al paso 4

### Información Específica:
- **Formulario:** `gestionUsuarios.cs`
- **Método:** `CrearUsuario(string nombre, string email, string password, Guid idFamiliaRol)`
- **Asignación automática:** Línea 120 de `UsuarioBLL.cs`

---

## CU-06.2: Modificar Usuario

**Actor Principal:** Administrador

**Precondiciones:**
- El usuario a modificar existe

**Postcondiciones:**
- Los datos del usuario han sido actualizados

### Flujo Principal:
1. El administrador selecciona un usuario
2. El administrador selecciona "Modificar"
3. El sistema carga datos actuales
4. El administrador modifica:
   - Nombre
   - Email
   - Contraseña (opcional)
   - Rol
5. El administrador confirma
6. El sistema valida cambios
7. El sistema actualiza el usuario
8. Si cambió contraseña: hashea con SHA-256
9. Si cambió rol: quita rol anterior y asigna nuevo
10. El sistema recalcula DVH
11. El sistema registra en bitácora
12. El sistema muestra mensaje de éxito

### Información Específica:
- **Método:** `ActualizarUsuario(Guid idUsuario, string nombre, string email, string password, Guid? idFamiliaRol)`
- **Cambio de rol:** `CambiarRol(Guid idUsuario, Guid idNuevaFamiliaRol)`

# CU 08 - PRÉSTAMOS/DEVOLUCIONES

## CU-08.1: Registrar Préstamo

**Actor Principal:** Bibliotecario, Administrador

**Precondiciones:**
- Existe material disponible
- Existe alumno sin préstamos atrasados

**Postcondiciones:**
- Se ha registrado un préstamo
- El ejemplar cambia a estado "Prestado"
- Se actualiza cantidad disponible

### Flujo Principal:
1. El usuario accede a "Registrar Préstamo"
2. El usuario busca y selecciona alumno por DNI
3. El sistema verifica que el alumno no tenga préstamos atrasados
4. El usuario busca y selecciona material
5. El sistema muestra ejemplares disponibles del material
6. El usuario selecciona un ejemplar específico
7. El sistema valida que el ejemplar esté disponible
8. El usuario ingresa fecha de devolución prevista
9. El usuario confirma
10. El sistema valida todos los datos
11. **El sistema inicia transacción (Unit of Work)**
12. El sistema cambia estado del ejemplar a "Prestado"
13. El sistema registra el préstamo
14. **El sistema confirma transacción (Commit)**
15. El sistema registra en bitácora
16. El sistema muestra mensaje de éxito

### Flujos Alternativos:
**3a. Alumno tiene préstamos atrasados:**
- El sistema muestra "El alumno tiene préstamos atrasados. Debe devolverlos antes de realizar un nuevo préstamo"
- Fin del caso de uso

**7a. Ejemplar no disponible:**
- El sistema muestra "El ejemplar no está disponible. Estado: [estado]"
- Retorna al paso 5

**14a. Error en transacción:**
- El sistema ejecuta Rollback
- Revierte cambios
- Muestra mensaje de error
- Fin del caso de uso

### Información Específica:
- **Formulario:** `registrarPrestamo.cs`
- **Clase BLL:** `PrestamoBLL.cs`
- **Método:** `RegistrarPrestamo(Prestamo prestamo)`
- **Transacción:** Líneas 113-137 de `PrestamoBLL.cs`
- **Unit of Work:** Garantiza atomicidad (ejemplar + préstamo)

---

## CU-08.2: Registrar Devolución

**Actor Principal:** Bibliotecario, Administrador

**Precondiciones:**
- Existe un préstamo activo

**Postcondiciones:**
- El préstamo cambia a estado "Devuelto"
- El ejemplar vuelve a estado "Disponible"
- Se registra la fecha de devolución real

### Flujo Principal:
1. El usuario accede a "Registrar Devolución"
2. El usuario busca préstamo por:
   - DNI del alumno
   - Código de ejemplar
3. El sistema muestra préstamos activos
4. El usuario selecciona el préstamo a devolver
5. El usuario verifica estado del material
6. Si está dañado, marca observación
7. El usuario confirma devolución
8. **El sistema inicia transacción**
9. El sistema marca préstamo como "Devuelto"
10. El sistema registra fecha de devolución
11. El sistema cambia estado del ejemplar:
    - A "Disponible" si está en buen estado
    - A "Dañado" si se reportó daño
12. **El sistema confirma transacción**
13. El sistema registra en bitácora
14. El sistema muestra mensaje de éxito

### Flujos Alternativos:
**11a. Material dañado:**
- El sistema cambia estado a "Dañado"
- El sistema registra observación
- El material NO queda disponible

### Información Específica:
- **Formulario:** Parte de `Form1gestionPrestamos.cs`
- **Método:** `MarcarComoDevuelto(Guid idPrestamo)`
- **Transacción:** Unit of Work para atomicidad

---
